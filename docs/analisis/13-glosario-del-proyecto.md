# 13 — Glosario Técnico del Proyecto

> **Propósito:** Definir los términos, parámetros, sufijos y conceptos con el significado **exacto** que tienen dentro del código de `c:\xampp\htdocs\ecommerce`, evitando sinónimos genéricos.

| Término real en código | Significado específico en este proyecto | Ubicación relacionada | Notas / Diferencias clave |
|---|---|---|---|
| **`suffix` (`_{entidad}`)** | Sufijo en singular que llevan todas las columnas de una tabla en plural (ej. tabla `users` → sufijo `user` → columnas `id_user`, `email_user`). Se pasa por query string (`&suffix=user` o `&suffix=admin`) en operaciones de autenticación y validación de tokens. | `api/Documentación-APIRESTFul.pdf` (pág. 4), `api/routes/services/{post,put,delete}.php` | Si no se envía en `POST`/`PUT`/`DELETE`, el código asume `"user"` por defecto. |
| **`relations` (`rel` y `type`)** | Palabra reservada usada como primer segmento de ruta (`GET /relations?rel=t0,t1&type=s0,s1`) para indicar a `GetModel` que debe construir un `INNER JOIN` en estrella desde la tabla principal `t0` hacia cada tabla secundaria `tk` usando la llave `t0.id_{sk}_{s0} = tk.id_{sk}`. | `api/routes/services/get.php:L28-72`, `api/models/get.model.php:L180-816` | No es una tabla de la base de datos; es un disparador en `get.php`. |
| **`linkTo` / `equalTo`** | Parámetros query separados por comas que especifican las columnas (`linkTo`) y valores exactos (`equalTo`) para filtrar con `WHERE col = :col` (o la columna objetivo en búsquedas `search` y rangos `between1`/`between2`). | `api/routes/services/get.php:L20-72`, `api/models/get.model.php:L81-174` | En `getRelDataFilter`, `linkTo` no se valida contra `information_schema`. |
| **`filterTo` / `inTo`** | Parámetros adicionales exclusivos de las consultas de rango (`between1`/`between2`) que agregan la condición `AND $filterTo IN ($inTo)`. | `api/models/get.model.php:L618-816`, `web/ajax/report-sales.ajax.php:L32` | Usado en reportes y dashboard para filtrar `filterTo=process_order&inTo=2`. |
| **`token=no&except={col}`** | Modo de excepción en `POST` y `PUT` de la API que omite por completo la validación de token JWT siempre que `{col}` sea el nombre de una columna existente en la tabla destino. | `api/routes/services/post.php:L68-94`, `api/routes/services/put.php:L55-82` | Usado por `web/` para verificar correo (`except=verification_user`), resetear clave (`except=password_user`), sumar vistas (`except=views_product`) y sumar ventas (`except=sales_product`). |
| **`type_variant` (`gallery` vs `video`)** | Define la naturaleza del producto comercializado en la tabla `variants`: `"gallery"` representa un producto físico con galería de imágenes (sujeto a envío con `process_order = 0..2`) y `"video"` representa un curso digital en video (entregado instantáneamente con `process_order = 2` y accesible en `/aprendizaje/{url_product}`). | `web/views/pages/product/product.php:L49-125`, `web/views/pages/thanks/thanks.php:L128-135`, `web/views/pages/aprendizaje/aprendizaje.php` | Un mismo `product` puede tener múltiples `variants`. |
| **`ref_cart` / `ref_order`** | Código numérico pseudoaleatorio generado en `PaymentsController::payment()` mediante `TemplateController::genCodec(1000)` (`rand(1000,9999).time()`) que agrupa todos los ítems de un mismo checkout y se envía en la URL de retorno `/thanks?ref={ref}`. | `web/controllers/payments.controller.php:L64`, `web/views/pages/thanks/thanks.php:L3-12` | Es el identificador de lote de compra; en cambio `uniqid_order` (`uniqid()`) identifica cada línea individual en `orders`. |
| **`order_cart` / `number_order`** | Identificador externo de la transacción devuelto por la pasarela de pago (el `order.id` de PayPal, el `payment.id` de DLocal o el `payment_id` de MercadoPago). Se guarda primero en `carts.order_cart` y luego se copia a `orders.number_order`. | `web/controllers/payments.controller.php:L119,178,249`, `web/views/pages/thanks/thanks.php:L76,147` | En MercadoPago queda vacío en `orders.number_order` por un bug de variable en memoria (`FIN-06`). |
| **`process_order`** | Estado numérico (`0` a `4`) del ciclo de vida de una línea de pedido en `orders`: `0` = Pendiente (Creando guía), `1` = En Proceso (En reparto), `2` = Entregado, `3` = Garantía, `4` = Devolución de dinero. | `web/ajax/data-orders.ajax.php:L140-178`, `web/views/pages/perfil/modules/compras.php:L127-172` | Solo los pedidos con `process_order == 2` se contabilizan como ingresos en el dashboard y reportes. |
| **`active_template`** | Columna de texto en `templates` que vale `"ok"` para la única plantilla visual activa del sitio y `"Null"` (string literal) para las inactivas. | `web/views/template.php:L108-134`, `web/ajax/templates.ajax.php:L26-56` | Si ninguna fila tiene `"ok"`, toda la aplicación renderiza `pages/500/500.php`. |
| **`method_user`** | Método de registro del cliente en `users`: `"directo"` (formulario con contraseña), `"google"` (Google GSI / OAuth) o `"facebook"` (Facebook Graph SDK). | `web/controllers/users.controller.php:L36,527,683`, `web/ajax/google.ajax.php:L61` | Los usuarios con `"google"` o `"facebook"` se crean con `password_user = NULL` y `verification_user = 1`. |
